# Hikyuu 接入实施计划（2026-09-26）

状态：实施中。Windows 本地已安装 Hikyuu 2.8.2；官方 `importdata` 已完成沪深北日线导入并生成正式快照，固定股票研究回测可直接读取快照。任务 API 和页面已接入，但 API → PostgreSQL → worker → 页面端到端、跨源数据质量、历史交易约束及目标环境部署仍待验收。操作步骤见[本地运行说明](./hikyuu-runbook.md)。

## 决策与范围

- 第一版 A 股历史回测采用 Hikyuu 作为计算引擎，不再计划自研另一套日频撮合、账户和交易主循环。QuantDash 保留 FastAPI 的任务、配置、权限边界和报告 API，以及现有 Next.js 界面。
- 回测所用历史 A 股行情通过 Hikyuu 官方提供的 `HikyuuTDX` / `importdata` 工具获取并导入 Hikyuu 存储。这里的“官方提供”指项目官方提供的下载/导入工具，**不表示** `pip install hikyuu` 附带完整历史数据库，也不表示所有原始行情由 Hikyuu 项目方生产。
- 现有 AkShare 实时行情、看板 K 线、新闻和 Tushare 基础资料/财务数据暂按现状服务；历史回测不得在 Hikyuu 数据缺失时静默退回 AkShare 即时查询。
- MVP 限 A 股日频、单一入门策略、固定回测区间。分钟/Tick、模拟盘和实盘不在本计划内。

## 目标架构

```text
HikyuuTDX / importdata -> Hikyuu 本地历史数据存储（首轮评估默认 HDF5）
                                  |
                                  v
Next.js -> FastAPI 回测任务/API -> Hikyuu 适配层 -> Hikyuu 回测执行
                     |                   |
                     |                   +-> 数据可用性/口径检查
                     +-> PostgreSQL 保存任务、输入清单、交易与报告

AkShare/Tushare -> 现有看板与补充数据；合格的历史辅助数据按日期接入回测
```

回测数据以固定的 Hikyuu 导入快照为准。导入完成后通过只读快照/版本化副本隔离后续增量更新，并保存文件或数据集校验摘要；单独记录批次号不足以保证旧行情仍可重放。PostgreSQL 可保存标准化副本供页面或其他模块查询，但不能作为另一套可独立变化的回测价格真相。每次运行保存 Hikyuu 版本、导入批次/完成时间、数据覆盖范围与校验摘要、复权口径、股票池和策略版本、费用与成交参数。

## 分阶段执行

### 0. 环境与能力核验

1. 锁定可用的 Hikyuu 版本，验证项目 Python 版本、Windows 开发环境及目标 Docker/Linux 镜像的 wheel/原生库兼容性，确定独立回测 worker 还是后端进程内执行；优先隔离耗时任务，不阻塞 FastAPI 请求。
2. 在隔离环境安装 Hikyuu，按[官方 README](https://github.com/fasiondog/hikyuu)运行 `HikyuuTDX` 完成首次配置，再用 `importdata` 验证可重复更新；明确数据目录、磁盘预算、备份及失败重试方式。
3. 实测可取得的 A 股与基准指数、时间跨度、日线字段、增量更新时效、分红送配/复权能力和数据条款；用最小样本验证 Hikyuu 多股票组合与平台信号的可适配性，形成样本清单。未验证的字段不写成已具备能力。

验收：选定股票与基准的 3 年样本可离线读取；两次导入不会产生重复或覆盖错误；缺失日期、失败批次和来源能查清；最小组合策略能在 Hikyuu 里运行。

### 1. 历史数据边界

1. 定义 Hikyuu 证券代码、交易日、OHLCV、成交额、复权类型与现有 `daily_bars`/`stock_profiles` 的映射；保留原始未复权价格用于模拟成交，明确指标计算采用的复权视图及除权除息处理。
2. 建立导入批次与数据质量记录：股票/指数覆盖、日期范围、重复/缺口、非交易日、异常价格、零成交、企业行为校验。API 返回明确的 `unavailable`/`incomplete`，不自动补造数据。
3. 交易约束依赖的历史 ST、停牌、涨跌停状态和按日指数成分必须分别核验来源与生效日期；Hikyuu 日 K 的缺口不能直接证明停牌，当前名称或当前指数成分不能替代历史值。缺失时先缩小策略范围或阻止正式回测。

验收：同一导入快照重复读取结果一致；缺少关键历史状态的日期不会被当作可交易日期。

### 2. 引擎适配与策略闭环

1. 将后续实现的策略信号、按日股票池和等权目标持仓映射到 Hikyuu 可执行的策略/资金管理组件，记录版本与参数。先以固定股票的 5 日 EMA 与其 10 日平滑线交叉策略跑通技术链路，再接入原定的 20 日动量/逐日股票池；避免同时维护另一套独立账户账本。
2. 用 Hikyuu 提供的能力实现日频执行、费用、滑点、T+1、停牌和涨跌停限制；逐项核对行为。框架缺少的 A 股约束通过单一适配层扩展，并用确定性样本验证，不能假定开箱即满足。
3. 统一时序：交易日收盘后形成信号，下一可交易日按明确的成交价规则执行；首版默认次日开盘价，若开盘不可成交则记录拒绝或延期原因。
4. 将成交、持仓、现金、净值和拒单原因标准化后存 PostgreSQL，供既定 `/api/backtests` 接口查询；任务运行与报告生成交给后台 worker。

验收：3 只股票、10 个交易日的固定样本可人工核对每笔交易及每日资产；同一输入快照重跑结果一致。

### 3. 报告与上线前验收

1. 生成收益、回撤、交易/持仓、基准和费用明细；明确每个指标的计算口径。
2. 用已核验的真实历史数据跑满 3 年，比较两次运行结果，并检查未来数据泄露、退市股遗漏、历史成分替代和除权除息影响。
3. 增加离线固定样本测试、导入一致性检查和失败恢复演练；报告注明数据覆盖和未通过的校验，未通过时不标记为“可用于决策”。

## 实施顺序与阻断条件

顺序为 **环境/官方导入验证 → 历史数据质量和逐日股票池 → 引擎适配与确定性回测 → 3 年真实样本与报告**。关键字段、数据版权/使用条款或目标部署环境兼容性无法确认时停在对应关口，先记录可复现证据，再调整范围。
